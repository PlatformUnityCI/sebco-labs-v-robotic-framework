# CONFIGURACIÓN Y AUTOMATIZACIÓN DEL ENTORNO DE DESARROLLO

**Proyecto:** `sebco-labs-v-robotic-framework`

**Entorno soportado:**  
<span style="color:#B0005A;"><strong>macOS (ARM64 e Intel)</strong></span>

---

# 1. Objetivo

Este documento define la configuración base del entorno de desarrollo orientado al ecosistema Node.js, automatización local y validación continua.

La guía centraliza:

- instalación inicial del entorno,
- herramientas de calidad estática,
- automatización mediante Git Hooks,
- validaciones en pipelines de CI,
- mantenimiento del repositorio.

El objetivo es mantener un flujo de trabajo:

- reproducible,
- consistente entre entornos,
- fácil de mantener,
- alineado con prácticas de integración continua.

---

# 2. Requisitos del sistema y diagnóstico

El proyecto utiliza herramientas de los ecosistemas Python y Node.js.

Para validar la procedencia de los binarios instalados localmente:

```bash
which python3
which node
which npm
```

---

## Referencia de entorno local

### Python 3

Administrado mediante Homebrew.

Ruta esperada:

```text
/opt/homebrew/bin/python3
```

Esto evita interferencias con el intérprete nativo de macOS.

---

### Node.js y NPM

Administrados mediante NVM (`Node Version Manager`).

Ruta esperada:

```text
/Users/<user_name>/.nvm/versions/node/...
```

NVM permite:

- aislar versiones de Node.js,
- evitar instalaciones globales del sistema,
- alternar versiones de forma controlada.

# 3. Instalación inicial del entorno

## Paso 1: instalar Homebrew

Instalar Homebrew si la máquina no cuenta con él:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

---

## Paso 2: instalar Python

```bash
brew install python@3.14
```

---

## Paso 3: instalar NVM

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
```

---

## Paso 4: recargar Zsh y configurar Node.js

```bash
source ~/.zshrc
nvm install 20.20.2
nvm use 20.20.2
```

---

## Paso 5: inicializar el proyecto Node.js

Ubicarse en la raíz del repositorio:

```bash
cd sebco-labs-v-robotic-framework
```

Inicializar el proyecto:

```bash
npm init -y
```

---

## Paso 6: instalar herramientas de desarrollo

```bash
npm install --save-dev prettier markdownlint-cli husky lint-staged
```

Estas dependencias permiten:

- formatear documentación,
- validar sintaxis Markdown,
- ejecutar validaciones automáticas antes de cada commit.

---

## Paso 7: inicializar Husky

```bash
npx husky init
```

Luego de inicializar Husky:

- configurar `package.json`,
- definir reglas de `lint-staged`,
- ajustar el hook `pre-commit`.

# 5. Automatización local y calidad estática

Node.js se utiliza en la raíz del proyecto para administrar herramientas de validación y automatización local.

---

## Herramientas utilizadas

### Prettier

Formateador de código multiplataforma.

Se utiliza para:

- mantener formato homogéneo,
- mejorar legibilidad,
- reducir diferencias de estilo entre commits.

Aplica principalmente sobre:

- archivos Markdown (`.md`),
- configuraciones JSON,
- scripts compatibles.

---

### Markdownlint

Linter para documentación Markdown.

Se utiliza para:

- validar estructura,
- detectar errores sintácticos,
- mantener consistencia visual.

---

### Husky

Administrador de Git Hooks.

Permite ejecutar validaciones automáticas antes de operaciones como:

- `commit`,
- `push`.

---

### lint-staged

Ejecuta tareas únicamente sobre archivos presentes en el staging area.

Esto reduce:

- tiempo de ejecución,
- validaciones innecesarias,
- procesamiento completo del repositorio.


El hook ejecuta automáticamente las validaciones configuradas antes de completar un commit.

# 8. Integración continua con GitHub Actions

El repositorio utiliza workflows separados para segmentar responsabilidades de validación.

---

## Workflow de validación Python

Archivo:

```text
.github/workflows/python-ci.yml
```

Este pipeline:

- valida instalación reproducible,
- verifica hashes,
- controla sincronización de dependencias.

```yaml
name: Python CI - Dependencias y Seguridad

on:
  push:
    branches: [main, robotic-framework]
  pull_request:
    branches: [main, robotic-framework]

jobs:
  audit-and-test:
    runs-on: ubuntu-latest

    steps:
      - name: Clonar el repositorio
        uses: actions/checkout@v4

      - name: Configurar Python 3.14
        uses: actions/setup-python@v5
        with:
          python-version: "3.14-dev"
          cache: "pip"

      - name: Actualizar herramientas base
        run: |
          python -m pip install --upgrade pip
          python -m pip install pip-tools

      - name: Validar instalación reproducible
        run: |
          pip install --require-hashes -r requirements.txt

      - name: Verificar sincronización de dependencias
        run: |
          pip-compile --generate-hashes requirements.in --dry-run
```

# 9. Mantenimiento del repositorio

El archivo `.gitignore` debe excluir:

- entornos virtuales,
- dependencias descargadas,
- cachés,
- artefactos temporales.

Configuración recomendada:

```text
# Python
.venv/
__pycache__/
*.pyc

# Node
node_modules/
npm-debug.log*

# Reportes y cachés
report/
.pytest_cache/
```

---

# 10. Recomendaciones generales

- Mantener Node.js administrado mediante NVM.
- Evitar instalaciones globales innecesarias.
- Ejecutar validaciones locales antes de subir cambios.
- Mantener workflows de CI simples y segmentados.
- Versionar configuraciones del entorno junto al repositorio.
- Centralizar documentación técnica dentro del proyecto.

La configuración está orientada a mantener consistencia entre entornos locales y pipelines automatizados sin agregar complejidad innecesaria.
